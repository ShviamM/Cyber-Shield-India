# Netraksh Android App – Play Store Compliance & Critical Fixes

You are a Senior Android Engineer, React Native Expert, and Google Play Policy Specialist.

Review the entire Netraksh codebase and implement the following changes while ensuring the application remains fully compliant with Google Play policies.

## Important Constraints

Do NOT introduce any permission that could cause Google Play rejection, including:

* READ_PHONE_STATE
* READ_CALL_LOG
* PROCESS_OUTGOING_CALLS
* Accessibility Service misuse
* Any permission requiring the app to become the default Phone app

The application must remain a Call Screening application and not a Dialer replacement.

---

# Critical Fixes Required

## 1. Lock Screen Incoming Call Detection

Current issue:

* Incoming caller popup works inconsistently.
* Popup sometimes appears only after opening the application.
* Lock-screen experience is unreliable.

Tasks:

* Audit the Call Screening Service implementation.
* Ensure incoming call detection works when:

  * App is killed
  * App is in background
  * Device is locked
  * Device screen is off

Implement:

* Foreground service where appropriate
* Full Screen Intent notifications
* Proper notification channels
* Wake lock handling (only where necessary)
* Android 12, 13, 14, 15 compatibility

Expected Result:

Incoming caller identification should appear consistently similar to Truecaller without violating Play Store policies.

---

## 2. Permission Validation Flow

Current issue:

Users can enable protection even when required permissions are missing.

Tasks:

Create a Protection Readiness Check.

Verify all required permissions before enabling protection:

* Call Screening Role
* Overlay Permission
* Notification Permission
* Full Screen Intent Permission

If any permission is missing:

* Show status as Incomplete Setup
* Prevent enabling protection
* Provide one-click navigation to the missing permission

Expected Result:

Protection cannot be enabled unless setup is 100% complete.

## 4. Background Service Stability

Tasks:

## 5. Improve Blocked Numbers Management

Important:

Do NOT attempt to sync blocked numbers with Android's native blocked-number provider.

Reason:

Android restricts this capability to default Phone/SMS applications.

Instead implement:

### In-App Block Management

Features:

* View blocked numbers
* Search blocked numbers
* Unblock numbers
* Block reasons
* Fraud history
* Bulk unblock

Display clear messaging:

"Numbers blocked in Netraksh are automatically rejected by Netraksh Call Protection."

Expected Result:

Users can manage blocked numbers easily without relying on Android's system blocklist.

# Features NOT To Implement

Do NOT implement:

1. Post-call "Was this spam?" popup triggered after call ends.
2. READ_PHONE_STATE based call tracking.
3. READ_CALL_LOG access.
4. Android native blocked-number synchronization.
5. Any feature requiring Netraksh to become the default Phone app.

These features are either restricted by Android or likely to create Google Play policy issues.

Focus only on compliant alternatives.

Provide production-ready code with detailed comments and explanations for every change.
